# تحليل ملفي Excel الحاليين

> الملفان مش "شيتات حسابات" عادية: **مفيش ولا معادلة واحدة** في أي خلية. الاتنين بيستخدموا كقاعدة بيانات لنظامين مبنيين على Google Apps Script (فيه Tokens للجلسات، ومعرّفات ملفات Google Drive، و`ATTENDANCE_SPREADSHEET_ID`). كل الحسابات (تأخير، خصم، مرتبات) كانت بتتعمل في كود السكربت، والشيت بيخزن النتايج والإعدادات بس.

## 1) `GHIS Attendance V2.xlsx` — نظام بصمة الحضور (تطبيق الموظف)

| الشيت | الغرض | الأعمدة | ملاحظات |
|---|---|---|---|
| `2026-10` | سجل الحضور الشهري (شيت لكل شهر بصيغة YYYY-MM) | كود الموظف، الاسم، التاريخ، وقت الحضور، نقطة الحضور، مسافة الحضور (م)، صورة الحضور، وقت الانصراف، نقطة الانصراف، مسافة الانصراف، صورة الانصراف | صف واحد لكل موظف في اليوم. "نقطة الحضور" = مكان مسموح (مثلًا "الملعب"، "النقطة صفر") والمسافة بالمتر منه ⇒ النظام كان بيعمل **Geofence بالـ GPS**. في صف وقت الحضور = وقت الانصراف بالظبط (بصمة واحدة بس). مسافة 7736م يعني بصم وهو بعيد ~7.7 كم. |
| `سجل فشل مطابقة الوجه` | سجل كل محاولة **مطابقة وجه** | كود، تاريخ ووقت، النتيجة (match)، المسافة (0.35–0.42)، العداد المتتالي، محتسب؟ | المسافة دي مسافة face-descriptor (أقل = أشبه). بعد عدد فشل متتالي الموظف بيتحول للمراجعة. |
| `بيانات الموظفين` | نسخة مختصرة (كود + اسم) | — | **منسوخة** من ملف قاعدة البيانات عن طريق "مزامنة". |
| `كلمات المرور` (مخفي) | كلمات سر الموظفين | كود، `salt:hash`، آخر تعديل | Hash من نوع SHA-256 مع Salt (32 + 64 حرف hex). |
| `سجل التحقق من الهوية` | سجل عمليات التحقق | كود، نوع العملية، التاريخ، النتيجة، السبب | فاضي. |
| `Sheet1` | فاضي | — | — |

## 2) `GHIS V2 Database.xlsx` — نظام الموارد البشرية (لوحة الإدارة) — 44 شيت

### أ. المستخدمين والصلاحيات والأمان
- **مستخدمو النظام**: اسم المستخدم، Hash، Salt، الصلاحية، نشط؟، تاريخ الإنشاء، آخر دخول. فيه مستخدم واحد `admin` بصلاحية "أدمن".
- **مستويات الصلاحيات**: أدمن (كل الأقسام: reports, employees, rules, salary, documents, backup, users)، HR، شئون قانونية وعاملين (بدون أقسام محددة).
- **مصفوفة الصلاحيات**: الصلاحية × الموديول × (View/Create/Update/Delete/Export/Upload/Restore) — فاضية.
- **الجلسات**: Tokens الجلسات (مدة 8 ساعات). *هتتلغي* في النظام الجديد (الجلسات هتبقى في السيرفر).
- **سجل النظام**: 46 حدث (auth.login, salaryTx.add, notification.create, holiday.sync…) ⇒ هيتنقل لسجل التدقيق.

### ب. الموظفين
- **بيانات الموظفين** (17 عمود): الكود، الاسم إنجليزي/عربي، القسم، تاريخ التعيين/نهاية الخدمة، معفى من البصمة، المسمى، الجنسية، التليفون، طريقة القبض، استلم أوراقه، الصورة (Drive ID)، خصم الصيف، خصم السنة الأولى، شهر أول علاوة، استثناء خصم السنة الأولى. فيه موظف واحد.
- **قوائم الأقسام والمسميات**: قسمين (الادارة، الامريكي غير نشط) و3 مسميات.
- **الأقسام المعفاة من البصمة**، **مواعيد خاصة لموظفين**.
- **سجل تعديلات بيانات الموظفين**: Audit لكل حقل (قديم/جديد/سبب/مستخدم).
- **صلاحيات حقول الموظف**: أي حقول يشوفها/يعدلها الموظف بنفسه (الاسم، التليفون، الجنسية، الصورة قابلة للتعديل؛ القسم والمسمى والتعيين عرض فقط).
- **طلبات تعديل بيانات الموظفين** + **حالة استكمال البيانات** + **مراجعة صور الموظفين** + **حالة مراجعة مطابقة الوجه**: سير عمل "الموظف يطلب ⇒ الإدارة تعتمد".
- **سجل مزامنة الموظفين**: مزامنة الموظفين لملف البصمة ⇒ *هتتلغي* لأن الاتنين هيبقوا قاعدة واحدة.

### ج. قواعد الحضور والخصم
- **قواعد المواعيد** (+ أرشيف): من/لحد تاريخ، موعد الحضور 08:00 والانصراف 15:00.
- **قواعد الخصم**: وحدة التأخير 25 دقيقة = 0.25 يوم، الغياب = 1 يوم، عدم بصمة الانصراف = 0.25 يوم، الانصراف المبكر (غير مفعّل)، وتدرّج الأذونات في الشهر: الأول 0، التاني 0.25، التالت 0.5، الرابع 0.75، الخامس فأكثر 1 يوم.
- **العطلات الرسمية** (مع مصدر وحالة ACTIVE/SUPERSEDED لنقل الإجازات) و**الإجازات الرسمية** (قديم ومكرر) و**الإجازات الشخصية المعتمدة**.
- **تعديلات الحضور**، **سجل الأذونات**، **سجل نسيان البصمة**، **إعفاءات التأخير المعتمدة**، **استثناءات إلزام الانصراف**، **سجل الخصومات الإضافية والجزاءات**.

### د. المرتبات
- **أنواع حركات المرتب** (إضافة/خصم + تصنيف) و**حركات المرتب** (موظف، نوع، من/لحد تاريخ، قيمة): فيها حركة راتب أساسي واحدة.
- **سلف الموظفين** (إجمالي، أقساط، بداية الخصم، قيمة القسط، الحالة).
- **فترات المرتبات** + **سجل إقفال الفترات** + **نسخ الإقفال الشهري** + **صفوف نسخ الإقفال** (Snapshot بالـ JSON لكل موظف عند الإقفال).
- **إعدادات المرتبات للسنة**، **سياسة خصم الربعين**، **تصنيف أقسام خصم الصيف**، **سجل خصم واسترداد الصيف**، **السنوات الدراسية**.

### هـ. المستندات والتحقيقات والإشعارات
- **أنواع المستندات** + **مستندات الموظفين** (رقم، تاريخ إصدار/انتهاء، تنبيه قبل الانتهاء — الإعداد العام 30 يوم).
- **التحقيقات** + **موظفو التحقيقات** + **مرفقات التحقيقات**.
- **التنبيهات والإشعارات** (4 إشعارات تجريبية) + **مستهدفو الإشعارات** (وقت الإظهار/القراءة/الإخفاء لكل موظف).
- **سجل النسخ الاحتياطية**، **الإعدادات العامة** (توليد الكود تلقائيًا = نعم).

## 3) العلاقات بين الملفين
```
بيانات الموظفين (Database) ──مزامنة──▶ بيانات الموظفين (Attendance)
          │ كود الموظف = المفتاح المشترك في كل الشيتات
          ├── حركات المرتب / السلف / المستندات / التحقيقات / الإشعارات
          └── سجل الحضور الشهري (Attendance) ◀── قواعد المواعيد + قواعد الخصم + العطلات (Database)
```

## 4) مشاكل لاحظتها في الوضع الحالي
1. **البيانات متكررة** في ملفين ومحتاجة مزامنة (وفيه محاولة مزامنة فشلت).
2. **Hash بـ SHA-256** (سريع جدًا ⇒ ضعيف ضد التخمين). هيتحول لـ Argon2id أول ما المستخدم يدخل.
3. **الـ Tokens بتتخزن نص صريح** في الشيت، وأي حد يقدر يفتح الشيت يقدر يسرق جلسة.
4. شيت لكل شهر في الحضور ⇒ صعب التقارير عبر الشهور.
5. تواريخ مخزنة بأشكال مختلفة (تاريخ Excel أحيانًا ونص ISO أحيانًا).
6. شيت "الإجازات الرسمية" فيه المناسبة متسجلة كتاريخ (6/10) بدل نص — بيانات غلط.
7. الإشعارات فيها بيانات تجريبية (عناوين زي 888888).
8. الصور على Google Drive (Drive File ID) — مش هتتنقل تلقائيًا، هتتسجل كمرجع.
